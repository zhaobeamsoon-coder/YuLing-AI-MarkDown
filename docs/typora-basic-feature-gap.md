# YuLing MD 与 Typora 基础功能差距清单

> 更新日期：2026-08-26
> 对比目标：只比较个人日常 Markdown 写作所需的基础能力，不追求完整复制 Typora。
> 状态说明：✅ 已具备；🟡 部分具备；❌ 缺失。

## 1. 结论

YuLing MD 已经打通“打开文档库—所见即所得编辑—自动保存—表格—图片—公式—导出—AI 知了”的核心流程，也已经拥有比 Typora 更适合本项目目标的可拖拽表格列宽与 AI 划词入口。

目前最影响其成为日常主力编辑器的，不是高级功能，而是以下基础能力：

1. 当前文档查找与替换。
2. 完整的基础格式入口和 H1–H6 标题选择。
3. 链接插入、编辑和打开。
4. 大纲与标题跳转。
5. 字数统计。
6. 标签关闭、手动保存、另存为和单文件打开。
7. 最近工作区、标签页恢复与崩溃草稿恢复。
8. 代码块语言选择和语法高亮。
9. 未知 Markdown 语法的无损往返保证。

### 2.6 YuLing MD 已有的差异化能力

这些能力不属于 Typora 基础功能缺口，不应在后续补基础功能时被削弱：

- AI 知了：划词后解释、关联、类比、补缺。
- 知了输入可独立编辑，不修改 Markdown 原文。
- 本地工作区全文检索和引用跳转。
- 知识卡片写回普通 Markdown。
- 表格列宽通过鼠标拖动，并在 `.yulingmd/layout.json` 中持久化。
- 微信公众号/小红书富文本复制。
- PDF 与长图分享。
- 图片粘贴后进入文档库资源目录，使用相对路径。
- 默认专注模式、无账号、无订阅、无遥测、BYOK/Ollama。

## 4. 实施边界

- Markdown 文件继续是唯一正文真源，不把用户文档迁入封闭数据库。
- 表格对齐使用标准 GFM；列宽继续作为应用布局数据独立保存，不污染正文。
- 不因补 Typora 基础功能而引入账号、YuLing 云端、遥测或隐藏上传。
- AI 知了只在用户主动操作时发起网络请求。
- 优先补齐 P0 的完整闭环，不一次性把 P1/P2 全部塞进工具栏。

- **我跑过 / I ran it**：检查了当前仓库的 `EditorPane`、`App`、`FileSidebar`、`ExportPanel`、Markdown 转换、Tauri 配置及相关测试，用于判定 YuLing MD 当前状态。
